# Database conventions

Source: Build Bible ch.10 and ch.11. Postgres 17 (compose, digest-pinned) is the system of record; ClickHouse is the analytics store.

- **Keys:** every primary key is a `uuid` (generated by the application, UUIDv7 preferred for index locality; `gen_random_uuid()` is acceptable as default). Natural identifiers (`workspace_id`, `seq`) appear in unique constraints, not as primary keys of tenant tables.
- **Time:** `timestamptz`, always UTC. Never `timestamp without time zone`. Daily research units are UTC dates (`date`) aligned to settlement day.
- **Money and amounts:** `numeric` (with explicit precision and scale where known) or `text` carrying a canonical decimal string. Never `real`, `double precision` or JS `number` for token amounts, fees or prices. Transport as strings; use exact decimal helpers.
- **Tenancy and RLS:** every table keyed by organization or workspace has `org_id`/`workspace_id` columns, `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`, and policies tied to a server-set session setting (never client-supplied). Tenant context is set per transaction by the kernel.
- **Roles:** migrations run as the owner/superuser role (`nearesis`). The application connects as `nearesis_app` (NOSUPERUSER, NOBYPASSRLS, created by `infrastructure/postgres/init/00-roles.sql`) so RLS always applies. Tests that prove isolation must connect as `nearesis_app`.
- **Migrations:** SQL files in `packages/kernel/migrations`, forward-only, numbered, applied in a single transaction, each with tests. No single migration changes the whole schema without tests.
- **Idempotency:** every mutating command carries an idempotency key; `commands` has `UNIQUE (workspace_id, idempotency_key)`. Replays return the original result. Optimistic concurrency uses `expected_version` (HTTP `If-Match`); 409 on stale revision.
- **Event journal:** one transaction validates actor and ACL, checks revision, applies state, appends `workspace_events` (`UNIQUE (workspace_id, seq)`) and an `outbox` row. Workers publish only after commit; consumers deduplicate by key.
- **Integrity:** foreign keys on evidence edges (tombstones are explicit); `UNIQUE (snapshot_id, raw_object_hash)`; hashes stored as lowercase hex SHA-256 text.
- **Queries:** parameterized only. No string-built SQL from user or agent input.
