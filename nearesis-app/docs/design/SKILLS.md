## Vetting detail

### frontend-design (ACCEPTED)

- Files: `SKILL.md` (pure instructions, ~60 lines), `LICENSE.txt`. No scripts, no network calls, nothing about credentials. The only URL strings are none; `grep` for `curl|wget|http|token|password|secret|eval` found only the word "token" in the sense of "design token system".
- What it teaches: ground the design in the subject and audience; two-pass process (write a compact token plan, then review that plan against the brief and revise anything that reads as a generic default, then build); typography carries personality, choose faces deliberately, set an explicit scale, keep lines under about 80 characters; structural devices (borders, numbering, dividers, labels) must encode information; non-user-triggered motion sparingly, motion that answers an action is welcome; a named list of "AI-generated design" tells; spend boldness in one place and remove one accessory; copy rules (sentence case, active voice, errors explain and never apologise, empty screens invite action); quality floor (responsive, visible focus, reduced motion, accessible, screenshots to critique).
- Concrete rules adopted for Nearesis (all reflected in `DESIGN_SPEC.md`):
  1. Plan first, then review: the token plan and its review against the brief are written down in DESIGN_SPEC section 1 ("Design plan and review"), including what was changed after review.
  2. Typeface: not Inter, not system default alone. Geist Variable (UI) and Geist Mono Variable (hashes, queries), self-hosted through `@fontsource-variable` so nothing loads from a CDN. One family, two cuts.
  3. Type scale 11 / 12 / 13 / 14 / 16 / 20 / 26 px, base 13 px for a dense data tool, weights 400 / 500 / 600 only, tabular numerals for every number.
  4. Line length: prose in cards and chat is capped at 58 to 62 characters (`max-width: 58ch` to `62ch`).
  5. No tracked-out ALL-CAPS eyebrow labels, no middle-dot joined meta strings, no spaced em dash labels, no arrow glyphs on buttons, no gradient washes. Section labels in the sidebar are plain sentence case, 12 px, muted.
  6. No uniform radius: 3 / 5 / 8 / 12 px by role (chip, control, card, overlay). No stacked identical soft shadows: cards use a 1 px border; only overlays carry a shadow.
  7. Colour carries meaning only: one restrained blue accent (focus, selection, primary action), status hues, the honesty hue, and the chart series. Neutral cool greys for surfaces. Not cream plus terracotta, not near-black plus acid green.
  8. Motion: no fade-and-slide-up on every section and no hover transition on every card. Motion answers an action (open, expand, approve, add, collapse) or marks a state change (patch applied, run state). One looping motion only (the live-run dot). Everything has a reduced-motion fallback.
  9. Boldness in one place: the honesty tag. SYNTHETIC and unattested data get a dashed, hatched label that cannot be mistaken for a status. Everything else stays quiet.
  10. Copy rules for UI text: sentence case, an action keeps one name through the whole flow ("Add to canvas" produces "on canvas"), errors say what failed and what to do ("This panel could not be drawn", code and message), empty states invite action and never apologise.
  11. Quality floor is enforced by tests: axe scan (0 serious or critical), reduced-motion check, keyboard focus ring check, 400 px layouts, screenshots reviewed.

### composition-patterns (ACCEPTED)

- Files read: `SKILL.md`, `README.md`, `AGENTS.md` (generated concatenation of the rules), `metadata.json`, `rules/*.md` (10 files). Markdown and JSON only. No scripts, no network calls, no credentials. `grep` for `curl|wget|fetch(|http|token|password|secret|eval|exec|rm -|npm|install` hit only an example link in a template file.
- What it teaches: avoid boolean-prop proliferation, use compound components and explicit variants, lift state into providers, children over render props, and React 19 APIs (no `forwardRef` needed for new code, `use()` over `useContext()`).
- Concrete rules adopted:
  1. Components take slots (`meta`, `toolbar`, `actions`, `notices`, `footer`, `inspector`) instead of `showX` booleans. `PanelCard` has no boolean mode props beyond state flags the data model already has (`selected`, `entering`).
  2. Explicit variants: `FreshnessBadge`, `CompletenessBadge`, `PanelStateBadge`, `ProvenanceChip` are separate components, not one `Badge` with a mode switch.
  3. Chat panel is controlled: all state (thread, runs, approvals) is passed in and all effects are callbacks (`onSubmit`, `onDecide`, `onCancel`, `onAddToCanvas`). The mock stream in the design lab is a provider-like hook outside the components, so apps/web can swap in the real SSE-backed store without touching the UI.
  4. Known deviation: `Button` and `IconButton` still use `forwardRef` (so Radix `asChild` and tooltip triggers can reach the DOM node). React 19 lets `ref` be a plain prop; switching these two is a small follow-up, listed in the handoff.

### Rejected, with reasons

- `web-artifacts-builder` (Anthropic): full SKILL.md, `scripts/init-artifact.sh`, `scripts/bundle-artifact.sh` and the `shadcn-components.tar.gz` listing were read. The scripts run `pnpm create vite`, install `latest` of many unpinned packages (Tailwind 3.4.1, Parcel, `html-inline`, 25 Radix packages) and `npm install -g pnpm` if pnpm is missing. That conflicts with the repo's pinned, minimum-release-age dependency policy and its no-global-install rule, and the skill targets single-file claude.ai artifacts, not a monorepo app. Its useful guidance is one line ("avoid excessive centered layouts, purple gradients, uniform rounded corners, and Inter") which `frontend-design` already covers and which is recorded in DESIGN_SPEC anti-AI rules.
- `theme-factory` (Anthropic): slide-deck oriented; ten preset themes whose fonts are DejaVu Sans and whose palettes are generic (Ocean Depths, Sunset Boulevard...). It tells the agent to show a PDF and wait for the user's pick, which does not fit this task. It would push the design toward exactly the preset look the owner rejected. Not installed.
- `canvas-design` (Anthropic): produces static posters (png/pdf) from a "design philosophy"; ships about 50 binary font files. Wrong tool for a data UI; no benefit, large footprint. Not installed.
- `web-design-guidelines` (Vercel): the skill body is a 30-line wrapper whose rules are fetched at run time from `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`. A skill that pulls live instructions from a mutable URL cannot be vetted at install time and the repo's rule is no network egress except named hosts. Rejected. If wanted later, a human can vet a pinned copy of that file and add it as a static file.
